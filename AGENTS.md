# Правила репозитория

Документация и комментарии на русском. До изменения поведения обновить normative
OpenSpec и тесты. Использовать Go 1.27.1 и закреплённые tools/*.mod; запускать
через go tool -modfile. Не добавлять GitHub Actions и расписания.
Перед commit и push выполнить go tool -modfile=tools/task.mod task check.
Не ослаблять проверки ошибок, TLS, context, ресурсов и архитектуры ради зелёного линта.
Каждый nolint содержит конкретную причину. Публичный API проверять external tests.
Инструкции хранить в AGENTS.md, skills в .agents/skills; использовать
repository-conventions и запускать его checker перед commit.

Примеры, собственные fixtures, inline-тесты, fuzz seeds, benchmark inputs и
trace links должны быть синтетическими и нейтральными. Использовать условные
ServiceIntegration, ExternalService, Request и Policy; не переносить имена,
адреса, расположение, идентификаторы устройств, настройки и сценарии личных
проектов. Для модели из существующего Go-сервиса сначала выделить общий контракт
и обезличить данные, затем переносить его в CML и примеры реализации.
Условные ссылки маркировать префиксом example.; реальные ссылки допустимы
только на нейтральный код и тесты, существующие в этом репозитории.
Сохранять upstream corpus и его атрибуцию; правило нейтральности относится
к собственным материалам проекта. В примерах установки использовать обычные
Go-команды; не добавлять сведения
о видимости репозиториев и пользовательские настройки аутентификации.
Проверять собственные материалы через scripts/check-examples.py; при очистке
истории дополнительно запускать его с --history. Не обходить эту проверку
переименованием личных объектов без обезличивания правил, описаний и trace links.

Нейтральность examples и fixtures не требует изменения намеренно заданной
Git-атрибуции. Имя и email автора коммитов сохранять по указанию пользователя.
